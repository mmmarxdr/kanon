`@kanon/mcp` exposes Kanon as Model Context Protocol tools for coding agents. The process uses stdio for the host-tool connection and REST for all communication with the Kanon API.

## Inventory

Exact surface: **49 tools = 26 core + 23 deferred**. Five deferred triage tools are retrieved via ToolSearch; all existing 44 contracts remain unchanged. Fixed ceilings: 5,350-byte topline descriptions and 1,950-byte server instructions.

## Startup

The entry point validates `KANON_API_URL` and `KANON_API_KEY`, resolves the optional client identity, finds the nearest `.kanon` binding, creates a typed API client, registers tool families, connects the stdio transport, and optionally starts an SSE client for workspace events.

## Tool families

- Projects and issue groups
- Issues and transitions
- Roadmap planning
- Cycles
- Work sessions and time capture
- Timesheets
- Documents and comments
- Members
- Capture-oriented helpers (including legacy `apply_proposal`)
- Issue triage (deferred): preview, persist, get, project list, dismiss

## Issue triage (host-mediated)

Enablement order: preview/search → get/list → persist/dismiss → retention.

1. **`preview_issue_triage`** — read-only `prepare` (deterministic; `aiIntent=none` or `host_assisted`) then optional `validate` with host suggestions. No Sampling assumption; hosts without a model stop after prepare.
2. **`persist_triage_proposal`** — explicit write of the exact returned preview + seal. Creates or deduplicates a typed proposal; never applies or mutates the Issue.
3. **`get_triage_proposal` / `list_triage_proposals`** — authorized read. List requires exactly one `projectKey` (compact project review queue only; no workspace-wide MCP queue).
4. **`dismiss_triage_proposal`** — terminal lifecycle write with an explicit reason.

Legacy `apply_proposal` remains for estimate/generic MCP proposals and must not be advertised as triage execution. Triage proposals are non-executable.

## Repository binding

A `.kanon` file binds a local repository to a Kanon workspace and project. Resolution starts from the process working directory and walks toward the Git root; the nearest valid binding wins. This lets one global MCP installation operate against different projects based on the directory where the coding agent starts.

## REST adapter

`KanonClient` owns transport concerns such as URL normalization, timeouts, bearer authentication, refresh-token exchange, provenance headers, typed API errors and endpoint-specific response shapes. MCP tool handlers should remain thin adapters around this client.

## Activity and live context

Every registered tool handler is wrapped so genuine tool use updates heartbeat activity. The background SSE client can consume workspace events, while graceful shutdown stops SSE and all heartbeat workers.

## Rollout and rollback (operator)

Enable capabilities only in this order:

1. **Schema** — additive triage ledger/policy migration verified; no Issue shape change.
2. **Apply guard / flags off** — triage-first legacy apply rejection + audit; all `TRIAGE_*_ENABLED` flags remain false until evidence passes.
3. **Read-only preview/search canary** — enable preview after `triage-preview-v1` evidence (authorized CTE + `LIMIT 11`, compact ≤16 KiB, P95 &lt;3s, zero domain writes).
4. **Get/list** — enable after `triage-proposal-list-v1` visibility-before-predicates, `LIMIT 51`, 32 KiB list / 64 KiB get, and list P95 target.
5. **Persist/dismiss** — enable `TRIAGE_PROPOSALS_ENABLED` and `TRIAGE_DISMISS_ENABLED` only after exact-dedup, supersession, and concurrency evidence; dismiss &lt;1s / ≤8 KiB under profile.
6. **Retention** — enable `TRIAGE_RETENTION_ENABLED` last; never shortens captured eligibility.

Canary gates (rolling five-minute windows, ≥100 completed requests/stage): unexpected stage errors &gt;1% page and disable that stage; typed degradation &gt;10% halt that stage; unexpected errors &gt;5% disable all triage flags. Any security/invariant violation stops all triage flags immediately. Alerts never mutate Issues, proposal bytes, or audit.

**Rollback** is flags-off / fix-forward: set `TRIAGE_PROPOSALS_ENABLED=false` first, then set `TRIAGE_DISMISS_ENABLED=false` and `TRIAGE_RETENTION_ENABLED=false` before disabling reads/preview as needed. Restart or recreate the API after changing these startup-parsed values; deployment automation must do this automatically. Verify representative requests for every disabled gate return `503 CAPABILITY_DISABLED`. Retain immutable rows, apply guard, tombstones, audit, and authorized recovery. Set `KANON_TRIAGE_TOOLS_ENABLED=false`, restart MCP, and verify discovery reports exactly the prior **44-tool** surface with no triage names. Only exact `true`/`false` values are accepted. Do **not** down-migrate enums/tables or delete audit rows in ordinary recovery. Destructive database rollback requires separate approval only after export/backfill and verification prove preserved history and compatibility.

Reference profiles (set `TRIAGE_PERF=1` for full 1,000-sample runs on PG16/Node20, 4 vCPU/8 GiB): `triage-preview-v1`, `triage-proposal-list-v1`.

<Warning>
The MCP package must never bypass the API and access Prisma or PostgreSQL directly. Doing so would duplicate authorization and domain invariants.
</Warning>
