## OPEN: main CI red — smoke-install.sh version drift

**Symptom**: CI job "Smoke test install.sh" fails 11/13 — `cp: cannot stat '.../kanon-mcp-0.5.0.tar.gz'`.

**Root cause**: `packages/setup/scripts/smoke-install.sh:31` hardcodes `KANON_MCP_VERSION="0.4.0"`, but `install.sh` was bumped to 0.5.0 (a64804c, pushed directly to main — CI did not run on that push). Fixture builds a 0.4.0 tarball; install.sh requests 0.5.0. Latent since a64804c; first exposed by PR #48's CI run. Unrelated to the register change (web tests + typecheck green).

**Proposed fix** (not yet applied): derive the version in smoke-install.sh from install.sh instead of hardcoding, so it never drifts on release bumps:

```bash
KANON_MCP_VERSION="$(grep -m1 '^KANON_MCP_VERSION=' "$REPO_ROOT/install.sh" | cut -d'"' -f2)"
```

**Next step**: branch `fix/smoke-install-version` → fix + (optionally) a guard test → PR. Consider creating a KAN issue first (relates to KAN-13 territory but distinct bug).
