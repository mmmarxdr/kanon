## Dependency and rollout gates

The implementation dependency order is deliberately stricter than code ownership order:

1. Additive schema, policy backfill, triggers, indexes, and migration evidence.
2. Triage-first legacy apply guard, audit-failure fail-closed behavior, and all flags off.
3. Read-only bounded search and deterministic/host-assisted preview.
4. Read-only proposal get and project-only list, including snapshot/cursor evidence.
5. Explicit persistence and dismiss only after migration, guard, source-conflict, exact-dedup, supersession, and concurrency evidence is green.
6. Retention/disposal last, after lifecycle and rollback evidence.

MCP registration may be present behind deferred discovery/feature flags, but persistence enablement is forbidden before steps 1–5 have passed. Preview, get, and list must never call the persistence service. The selected chain strategy is `stacked-to-main`: each PR merges to `main` in order, the next PR starts from updated `main`, and off-by-default flags preserve safe incremental integration.
